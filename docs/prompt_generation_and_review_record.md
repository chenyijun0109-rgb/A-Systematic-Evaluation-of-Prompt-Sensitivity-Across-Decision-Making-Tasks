# Prompt Generation and Review Record

**Record date:** 2026-06-14  
**Current protocol:** Prompt Generation Protocol 1.3  
**Purpose:** Record exactly how the nine prompt variants were generated,
which API controls were fixed, and how human review changed the generated
candidates before experimental use.

## 1. Method Boundary

The prompt-generation model did not design the cognitive tasks. The three
baseline prompts were constructed first from the task literature, local human
datasets, and implemented task rules:

```text
prompts/bandit/baseline.md
prompts/igt/baseline.md
prompts/bart/baseline.md
```

The model was used as a constrained rewriting tool. It generated three
candidates from each baseline:

| Task | Generated conditions |
|---|---|
| Horizon | `detailed`, `role_human`, `uncertainty_emphasis` |
| IGT | `detailed`, `role_human`, `reward_loss_emphasis` |
| BART | `detailed`, `role_human`, `risk_emphasis` |

This produced nine generated candidates. The three baselines were not
generated by this API call.

## 3. Instruction Given to the Generator

The generator received one rendered version of
`prompts/generation/controlled_prompt_variant_generation_protocol.md` for each task. The exact reusable
instruction is retained verbatim in that file. Its operational content was:

```text
You are assisting with prompt construction for a cognitive
decision-making experiment involving large language models.

Your role is strictly limited to constrained rewriting. The supplied baseline
is frozen and must not be rewritten. You must produce exactly three variants
that preserve all task facts and technical requirements in that baseline.

Inputs:

Task identifier:
[TASK_IDENTIFIER]

Canonical task specification:
[PASTE_CANONICAL_TASK_SPECIFICATION]

Frozen baseline prompt:
[PASTE_BASELINE_PROMPT_VERBATIM]

Task-specific emphasis condition:
Condition name: [CONDITION_NAME]
Permitted emphasis: [DEFINE_INFORMATION_TO_MAKE_MORE_SALIENT]

Non-negotiable constraints:

1. Do not change, remove, or add any task fact.
2. Do not change the available actions or their meanings.
3. Do not change the number or structure of trials, games, blocks, or
   balloons.
4. Do not change feedback, reward, loss, risk, payoff, or stopping rules.
5. Do not add probabilities, examples, or numerical values absent from the
   frozen baseline.
6. Do not add strategy advice, identify an optimal action, or suggest how to
   maximise performance.
7. Preserve the neutral total-reward objective without strengthening it into
   a strategy instruction.
8. Do not mention behavioural metrics, latent mechanisms, hypotheses, or
   expected effects.
9. Do not mention human benchmark data, published results, canonical task
   names, authors, papers, or datasets.
10. Preserve every template placeholder exactly, including braces, spelling,
    and number of occurrences.
11. Preserve the required response format and legal response tokens exactly.
12. Vary only the factor authorised for each condition.

Conditions to produce:

1. detailed
Explain and organise the same facts more explicitly. Do not introduce
additional information, examples that imply a strategy, or extra feedback.

2. role_human
Frame the model as taking the role of a human participant completing the same
task. Do not claim that the model has human emotions, cognition, preferences,
or lived experience. Do not ask it to reproduce typical human behaviour.

3. [CONDITION_NAME]
Make only [DEFINE_INFORMATION_TO_MAKE_MORE_SALIENT] more salient. The
emphasised information must already appear in the frozen baseline. Do not
imply which action should be selected.

Output exactly three labelled Markdown sections followed by a constraint
audit. Preserve the observation placeholder and legal response format.
```

The block above records the substantive instruction. The file
`controlled_prompt_variant_generation_protocol.md` is the authoritative verbatim version, including all
headings, Markdown formatting, and the exact output template. The three
rendered `request.md` files listed below are the exact prompts sent to the API

## 6. Human Review

Review was based only on task equivalence and manipulation isolation. Pilot
behavioural results were not used to select wording.

### First review: factual equivalence

The first review corrected factual drift:

- Restored "may differ" where the generated candidate stated that reward
  patterns definitely differed.
- Removed IGT explanations of net-outcome arithmetic that were absent from
  the baseline.
- Restored BART wording about unknown explosion outcomes rather than adding a
  claim about differing explosion probabilities.
- Removed unintended risk emphasis from BART `detailed` and `role_human`.
- Removed outer response fences, labels, and the generator's audit table from
  final prompt files.

### Second review: strict control-variable isolation

A stricter audit found that the first reviewed versions still changed
non-target wording and strengthened the reward objective. The following
changes were therefore made:

| Condition type | Final review modification |
|---|---|
| All nine variants | Restored the exact baseline objective: `Your aim is to finish the full task with as much total reward as possible.` |
| All `role_human` prompts | Restored the complete baseline verbatim and added only: `Take the role of a human participant completing this task.` |
| Horizon `uncertainty_emphasis` | Restored the complete baseline except for the uncertainty paragraph, which adds that each observation provides partial/incomplete information |
| IGT `reward_loss_emphasis` | Restored the complete baseline except for the feedback sentence, which asks the participant to pay particular attention to reward, loss, net outcome, and cumulative score |
| BART `risk_emphasis` | Restored the complete baseline except for the pump/explosion paragraph, which explicitly describes the existing trade-off |
| All `detailed` prompts | Retained the generated explanatory organisation but restored the exact neutral objective and removed unsupported facts |

This second review is a control-variable correction. It does not alter task
rules and was completed before collecting new data with this prompt version.

## 7. Final Isolation Rules

The final prompt matrix obeys these mechanical constraints:

1. Every prompt contains the same neutral objective sentence.
2. A `role_human` prompt becomes byte-identical to its baseline after removing
   its one role-framing sentence.
3. A task-specific emphasis prompt becomes byte-identical to its baseline
   after restoring its one authorised paragraph.
4. Detailed prompts may reorganise existing facts but cannot add rules,
   feedback, probabilities, or strategy information.
5. All prompts contain exactly one `{observation}` placeholder.
6. Legal response tokens are identical within each task.

These constraints are enforced in `tests/test_prompt_dry_run.py`.
